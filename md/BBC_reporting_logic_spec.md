# BBC Consulting — логика управленческой отчётности (ДДС / ОПиУ / Баланс)

Спецификация утверждённой логики для дальнейшей автоматизации / построения мини-сервиса.

## 1. Контекст

- Компания: BBC Consulting, группа из 8 точек, обслуживающих ~200 клиентов.
- 4 направления услуг: налоговый отдел, бухгалтерский отдел, юридический отдел, кадровый отдел (HR).
- По каждому направлению: разовые услуги + ежемесячная абонентская плата.
- Источники данных:
  - **Журнал операций** — все юрсчета/выписки банка, факт оплаты (кассовый метод).
  - **Реестр продаж** — даты начала/окончания периода услуги по каждому договору абонентской платы (основа для начисления).
  - **Табель учёта рабочего времени** — по сотрудникам, фиксирует фактически отработанные дни; источник для деления ФОТ по циклам.

## 2. Структура отчёта

Один лист, один столбец = один календарный месяц. Сверху вниз: **ДДС → ОПиУ → Баланс**.

## 3. ДДС (движение денег)

- Строго календарный месяц (01 – 30/31), основан на факте оплаты из Журнала операций.
- Циклы начисления (см. ниже) на ДДС не влияют — это чистый денежный поток.
- Строки: сальдо на начало, поступления (по категориям), списания (по категориям), сальдо на конец.
- Сальдо на конец текущего месяца = сальдо на начало следующего.

## 4. ОПиУ (по методу начисления) — два внутримесячных цикла

Ключевое решение: каждый календарный месяц делится на **два начислительных цикла**:

- **Цикл 1** — дни 01–15. Относится к "предыдущему" начислительному месяцу (хвост цикла абонентки, начавшегося 16-го числа прошлого месяца).
- **Цикл 2** — дни 16 – конец месяца (15 или 16 дней в зависимости от длины месяца). Относится к "следующему" начислительному месяцу.
- Итог ОПиУ за календарный столбец = **сумма показателей Цикла 1 и Цикла 2**.
- Правило для месяцев с 31 днём: Цикл 2 = 16 дней (16–31), граница календарная, не жёстко 15/15.

### 4.1. Выручка

- Признаётся по 4 направлениям (налоговый / бухгалтерский / юридический / HR).
- Источник — Реестр продаж: дата начала периода услуги определяет, в какой цикл (и, соответственно, в какой начислительный месяц) попадает доход.

### 4.2. ФОТ (зарплата)

- Реальная выплата сотруднику — единой суммой, календарный месяц целиком (01–30/31). Сотруднику разбивка не раскрывается.
- Для внутреннего учёта каждый сотрудник делится на "отработал Цикл 1" / "отработал Цикл 2".
- **Решено:** деление — по фактически отработанным дням, а не по календарной пропорции. Источник — **табель учёта рабочего времени**, отдельный массив данных, фиксируется наравне с Журналом операций и Реестром продаж. Единица табеля — **дни (0 или 1 за день)**.
- Формула (оклад): `ФОТ_Цикл = ФОТ_месяц × Отработанные_дни_в_цикле / Отработанные_дни_за_месяц`.
- **Отпуска/больничные — отдельная строка расхода**, не через пропорцию оклада: дни отпуска/больничного исключаются и из числителя, и из знаменателя формулы выше (т.к. отпускные/больничные считаются по среднему заработку, а не по окладу за день). Начисление отпускных/больничных делится между циклами по календарным дням самого отпуска/больничного, пропорционально своей отдельной базе.
- Налоги на ФОТ (п. 4.4) наследуют ту же пропорцию, что и оклад (без отпускных/больничных, которые облагаются отдельно).

### 4.3. Аренда

- Делится пропорционально дням цикла: `Аренда_Цикл1 = Аренда × 15 / Дней_в_месяце`, `Аренда_Цикл2 = Аренда × (Дней_в_месяце − 15) / Дней_в_месяце`.
- Арендодателю разбивка не раскрывается — платёж физически один, деление только для внутреннего ОПиУ.

### 4.4. Налоги на ФОТ (ИПН, соц. отчисления, ОПВ и т.п.)

- Зеркалят разбивку самого ФОТ — те же пропорции/логика по циклам.

### 4.5. Прочие операционные расходы (закуп и т.п.)

- Кассовый метод = метод начисления в один момент: расход не создаёт остатка/актива на балансе, поэтому относится целиком на тот цикл, в дату которого попала фактическая трата (без пропорционального дробления).

### 4.6. Прочие налоги (КПН годовой, поквартальные и т.п.)

- Не привязаны к 15-дневным циклам физически.
- **Открытый вопрос:** логика начисления ещё не определена, требует отдельного решения. Пока — одна календарная строка без деления на циклы, не блокирует остальную модель.

## 5. Баланс (мост между ДДС и ОПиУ)

Принцип: расхождения между фактом оплаты (ДДС) и признанием по начислению (ОПиУ) не решаются сдвигом периодов, а **оседают на балансе** как реконсиляционные счета — отдельно по каждому из двух циклов:

- **Активы:**
  - Денежные средства = сальдо на конец периода из ДДС.
  - Дебиторская задолженность клиентов — начислено (по циклу), не оплачено. Отдельно по Циклу 1 и Циклу 2, затем сумма.
- **Обязательства:**
  - Доходы будущих периодов (авансы клиентов) — оплачено вперёд, доход по циклу ещё не признан. Отдельно по Циклу 1 и Циклу 2 — это ключевой механизм, снимающий конфликт между датой оплаты и датой признания дохода.
  - Кредиторская задолженность по ФОТ — начислено, не выплачено, отдельно по циклам.
  - Прочая кредиторская задолженность — аренда / налоги на ФОТ / прочие расходы / прочие налоги, начислено не выплачено (пока одной строкой, без разбивки по циклам — возможное направление доработки).
- **Капитал:**
  - Нераспределённая прибыль (накопительно) = прошлый остаток + прибыль ОПиУ прошлого периода.
  - Прибыль текущего периода = прибыль ОПиУ за календарный месяц (сумма обоих циклов).
- Проверка: Активы = Обязательства + Капитал (должно сходиться в 0).

## 6. Итоговая логика сведения

1. ДДС фиксирует факт по календарю.
2. ОПиУ признаёт доходы/расходы по двум 15/16-дневным циклам внутри календарного месяца.
3. Разница между ДДС и ОПиУ по каждому циклу превращается в баланс (дебиторка / доходы будущих периодов / кредиторка).
4. Итог по календарному месяцу = сумма обоих циклов — не требует пересчёта задним числом при появлении новых данных.

## 7. Открытые вопросы (не закрыты, требуют решения)

- Логика начисления "прочих налогов" (КПН, поквартальные/годовые платежи).
- Нужно ли разносить "прочую кредиторскую задолженность" по циклам так же, как дебиторку и доходы будущих периодов.
